# DevSecOps Lab - Complete Step-by-Step Guide

## Overview
This comprehensive guide walks you through setting up a DevSecOps project with Spring Boot, Docker, and GitHub Actions CI/CD pipeline.

## Part 1: Git & GitHub Setup

### 1.1 Initialize Git Repository

```bash
# Initialize Git in your project
git init

# Check status
git status
```

### 1.2 Create GitHub Repository

1. Go to [GitHub](https://github.com) and log in
2. Click **"New Repository"** (green button or + icon)
3. Repository name: `tp-devsecops`
4. **Do NOT check** "Initialize with README"
5. Click **"Create repository"**
6. Copy the repository URL (should look like: `https://github.com/YOUR_USERNAME/tp-devsecops.git`)

### 1.3 Add Files and Commit

```bash
# Add all files to staging
git add .

# Create initial commit
git commit -m "Initial commit"

# Check current branch name
git branch

# Rename to main (if needed)
git branch -M main
```

### 1.4 Link to GitHub and Push

```bash
# Link local repository to GitHub
# Replace YOUR_USERNAME with your actual GitHub username
git remote add origin https://github.com/YOUR_USERNAME/tp-devsecops.git

# Verify remote
git remote -v

# Push to GitHub
git push -u origin main
```

**✅ Verify**: Visit your GitHub repository URL. You should see all your files!

## Part 2: Java Application Setup

### 2.1 Check Tool Versions

```bash
# Check Docker
docker --version

# Check Java
java -version

# Check Maven
mvn -version
```

**Expected Output**:
- Docker: 28.1.1 or higher ✅
- Java: 21.0.1 or higher ✅
- Maven: 3.6+ (Need to install if not available)

### 2.2 Install Maven (if needed)

**Option 1: Chocolatey (Recommended for Windows)**
```powershell
choco install maven
```

**Option 2: Manual Installation**
1. Download from: https://maven.apache.org/download.cgi
2. Extract to `C:\Program Files\Apache\maven`
3. Add to PATH: `C:\Program Files\Apache\maven\bin`
4. Restart terminal and verify: `mvn -version`

**Option 3: Use Maven Wrapper (Included in this project)**
```bash
# Windows
.\mvnw.cmd clean package

# Linux/Mac
./mvnw clean package
```

### 2.3 Project Structure

The project follows Maven's standard directory structure:

```
secure_app/
├── .github/
│   └── workflows/
│       └── ci.yml           # CI/CD pipeline
├── src/
│   └── main/
│       ├── java/
│       │   └── com/
│       │       └── example/
│       │           └── democyber/
│       │               └── DemocyberApplication.java
│       └── resources/
│           └── application.properties
├── target/                   # Generated by Maven (gitignored)
├── Dockerfile
├── pom.xml
├── .gitignore
```

### 2.4 Build the Application

```bash

mvn clean package

```

### 2.5 Test Locally

```bash

java -jar democyber-0.0.1-SNAPSHOT.jar
```

## Part 3: Docker

### 3.1 Check Docker Hub Username

1. Go to [Docker Hub](https://hub.docker.com)
2. Log in and note your username (you'll need this!)

### 3.2 Build Docker Image

```bash
# Build the image
# Replace YOUR_DOCKERHUB_USERNAME with your actual Docker Hub username
docker build -t YOUR_DOCKERHUB_USERNAME/democyber:latest .

# Expected: Successfully built and tagged
```

### 3.3 Test Docker Image Locally

```bash
# Run the container
docker run -p 8080:8080 YOUR_DOCKERHUB_USERNAME/democyber:latest

# Open browser: http://localhost:8080
# Expected: "Hello from Democyber 123!"

# Stop: Ctrl+C
```

**Note**: The `-p 8080:8080` flag maps port 8080 from the container to port 8080 on your PC.

### 3.4 Push to Docker Hub

```bash
# Login to Docker Hub
docker login
# Enter your username and password

# Push the image
docker push YOUR_DOCKERHUB_USERNAME/democyber:latest

# Expected: Successfully pushed
```

**✅ Verify**: Go to Docker Hub → Repositories. You should see `democyber`!

### 3.5 Test Image from Docker Hub

```bash
# Pull and run the latest version from Docker Hub
docker run --pull always -p 8080:8080 YOUR_DOCKERHUB_USERNAME/democyber:latest

# This forces Docker to download the latest version
```

## Part 4: CI/CD Pipeline with GitHub Actions

### 4.1 Create Docker Hub Access Token

1. Log in to [Docker Hub](https://hub.docker.com)
2. Click your profile → **Account Settings**
3. Go to **Security** → **Personal Access Tokens**
4. Click **New Access Token**
5. Description: `github-actions`
6. Permissions: **Read & Write**
7. Click **Generate**
8. **⚠️ IMPORTANT**: Copy the token immediately (you won't see it again!)

### 4.2 Add Secrets to GitHub

1. Go to your GitHub repository: `https://github.com/YOUR_USERNAME/tp-devsecops`
2. Click **Settings** tab
3. In left sidebar: **Secrets and variables** → **Actions**
4. Click **New repository secret**

**Add Secret 1:**
- Name: `DOCKERHUB_USERNAME`
- Value: Your Docker Hub username
- Click **Add secret**

**Add Secret 2:**
- Name: `DOCKERHUB_TOKEN`
- Value: The token you copied from Docker Hub
- Click **Add secret**

**✅ Verify**: You should see both secrets listed (values are hidden).

### 4.3 GitHub Actions Workflow

The workflow file is already created at `.github/workflows/ci.yml`. It will:

1. **Trigger**: Automatically run on every push or pull request to `main` branch
2. **Steps**:
   - Checkout code
   - Set up Java 21
   - Compile Java code
   - Build project with Maven

### 4.4 Test the Pipeline

```bash
# Make a small change
echo "# DevSecOps Lab" > TEST.md

# Commit and push
git add .
git commit -m "Test CI/CD pipeline"
git push origin main
```

**✅ Verify**: 
1. Go to GitHub repository → **Actions** tab
2. You should see your workflow running
3. Wait for it to complete (green checkmark = success!)

## Lab Questions & Answers

### Q1: Screenshot of successful pipeline run
**Answer**: Go to GitHub → Actions tab → Click on your workflow run → Take a screenshot showing all steps completed successfully with green checkmarks.

### Q2: What would happen if one of the steps fails (e.g., Java setup)?
**Answer**: 
- The workflow would stop at the failed step
- All subsequent steps would be skipped
- The build status would show as "failed" (red X)
- GitHub would send a notification (if configured)

**How to identify and fix**:
1. Click on the failed workflow run
2. Click on the failed step to see detailed logs
3. Look for error messages (usually in red)
4. Common issues:
   - Wrong Java version specified
   - Missing dependencies
   - Syntax errors in code
   - Network issues downloading dependencies
5. Fix the issue locally, commit, and push again

**Example**: If Java 21 setup fails:
```yaml
# Check if the version is correct
- name: Set up JDK 21
  uses: actions/setup-java@v3
  with:
    java-version: '21'  # Make sure this matches your project
    distribution: 'temurin'
```

### Q3: Why specify branch (main) as trigger? What if we used * instead?
**Answer**:

**Why specify `main`**:
- **Controlled deployment**: Only production-ready code in `main` triggers builds
- **Resource efficiency**: Doesn't waste CI/CD resources on every branch
- **Security**: Prevents untrusted code in feature branches from running pipelines
- **Best practice**: main/master is the stable branch

**If we used `*` (all branches)**:
- ✅ **Pros**:
  - Every branch gets tested automatically
  - Catch issues early in feature branches
  - Good for large teams with many active branches
  
- ❌ **Cons**:
  - **Resource waste**: Pipeline runs for every branch, even experimental ones
  - **Slower feedback**: Queue builds up with many branches
  - **Cost**: GitHub Actions has usage limits (free tier: 2000 minutes/month)
  - **Noise**: Too many notifications
  - **Security risk**: Anyone with write access could trigger workflows

**Security Example**:
```yaml
on:
  push:
    branches: [ * ]  # ⚠️ DANGEROUS! Any branch can trigger pipeline
```

If a malicious contributor pushes code to a branch, it would automatically run your CI/CD pipeline, potentially:
- Consuming all your CI/CD minutes
- Exposing secrets (if misconfigured)
- Running malicious code in CI environment

**Best Practice**:
```yaml
on:
  push:
    branches: [ main ]  # ✅ Only main branch triggers deployment
  pull_request:
    branches: [ main ]  # ✅ Test PRs before merging
```

## Troubleshooting

### Issue: Maven not found
**Solution**: Install Maven (see Section 2.2) or use Maven wrapper (`mvnw`)

### Issue: Port 8080 already in use
**Solution**: 
```bash
# Stop existing Java process or use different port
docker run -p 8081:8080 image  # Map to different port
```

### Issue: Docker build fails
**Solution**: 
- Make sure you ran `mvn clean package` first
- Check if `target/democyber-0.0.1-SNAPSHOT.jar` exists

### Issue: GitHub Actions fails
**Solution**:
- Check logs in Actions tab
- Verify secrets are set correctly
- Ensure pom.xml has correct Java version (21)
